API Rate Limits

Standard Acme Cloud API clients are limited to 1,000 requests per minute per API key. This limit applies per key, not per IP address, so multiple services sharing a key share the same budget.

Exceeding the limit

When a client exceeds the limit, the API returns an HTTP 429 response with the internal error identifier ERR_RATE_4290 in the response body. 

HTTP/1.1 429 Too Many Requests
Retry-After: 12
Content-Type: application/json

{
  "error": "ERR_RATE_4290",
  "message": "Rate limit exceeded. Retry after 12 seconds."
}

Recommended client behavior

  • Respect the Retry-After header when present.
  • Use exponential backoff with jitter for retried requests.
  • Cache responses where possible to reduce request volume.
  • Contact your account manager if your integration legitimately needs a higher limit; enterprise plans support raised limits.

Rate limit headers

Every response includes headers describing the caller's current rate-limit status:

  • X-RateLimit-Limit — the limit for the current window.
  • X-RateLimit-Remaining — requests remaining in the current window.
  • X-RateLimit-Reset — seconds until the window resets.
